# مصفوفة الأدوار والصلاحيات — USER_ROLES_PERMISSIONS

النموذج: **RBAC + نطاق بيانات (Data Scope)**. الصلاحية = *ماذا يستطيع* (الدور) × *على أي بيانات* (النطاق) × *حتى أي مبلغ* (حد الاعتماد).

---

## 1. الأدوار

| الرمز | الدور | النطاق الافتراضي |
|---|---|---|
| `technician` | الفني | ذاتي |
| `employee` | موظف | ذاتي |
| `supervisor` | المراقب | فريقه (من يتبعونه مباشرة) |
| `engineer` | المهندس | المشروع |
| `project_manager` | مدير المشروع | المشروع |
| `branch_manager` | مدير الفرع | الفرع |
| `branch_accountant` | محاسب الفرع | الفرع |
| `procurement` | إدارة المشتريات | الشركة |
| `finance` | الإدارة المالية | الشركة |
| `final_approver` | صاحب الاعتماد النهائي | الشركة |
| `sysadmin` | مدير النظام | الشركة (إداري فقط، لا اعتماد مالي) |

يمكن للمستخدم أن يحمل أكثر من دور، ولكل دور نطاقه المستقل (مثال: مهندس في مشروع أ، ومدير مشروع في مشروع ب).

## 2. النطاقات

| النطاق | يرى |
|---|---|
| ذاتي | عهده ومصروفاته وطلباته فقط |
| فريق | ما سبق + بيانات من `manager_id` لديهم = هو |
| مشروع | كل ما يخص المشروع المحدد في `user_roles.scope_id` |
| فرع | كل مشاريع وموظفي الفرع |
| شركة | كل بيانات الشركة |

**قاعدة صارمة:** لا يرى أي مستخدم بيانات شركة أخرى (مفروض في قاعدة البيانات)، ولا بيانات مشروع آخر خارج نطاقه (مفروض في الـ API ومختبَر).

## 4. قواعد الحوكمة

1. **فصل المهام:** من أنشأ العملية لا يعتمدها (مفروض في قاعدة البيانات SK010)، إلا إذا سمحت خطوة محددة بذلك صراحة.
2. **مدير النظام لا يعتمد مالياً.** يدير الحسابات فقط. هذا يمنع أن يمنح شخص نفسه صلاحية ثم يعتمد بها.
3. **تغيير الأدوار يُسجَّل** في سجل التدقيق مع القيمة قبل وبعد.
4. **حد الاعتماد** يُقارن بإجمالي المصروف شاملاً الضريبة؛ ما يتجاوزه يُصعَّد تلقائياً للمستوى الأعلى.
5. **تعارض المصالح:** المحاسب لا يدقق حافظة عهدته الشخصية.
6. **الجلسات:** تحديد الأجهزة المصرح بها، وإلغاء الجلسة عن بُعد، وMFA إلزامي لأدوار المالية والاعتماد النهائي ومدير النظام.

## 5. اختبارات الصلاحيات المخطط لها (المرحلة 6)

- فني يحاول قراءة عهدة فني آخر → 404.
- مهندس مشروع أ يحاول قراءة مصروف مشروع ب → 404.
- مراقب يعتمد مصروفاً يتجاوز حده → يُصعَّد ولا يُعتمد.
- مدير نظام يحاول اعتماد مصروف → 403.
- مستخدم يعتمد طلبه → مرفوض (SK010).
- مستخدم شركة ب يرى بيانات شركة أ → صفر نتائج (مختبَر: T26).

## 6. تسجيل الدخول والحسابات المرتبطة (الإصدار 0.3)

| الطريقة | كيف تعمل |
|---|---|
| البريد أو الرقم الوظيفي + كلمة المرور | كلمة المرور مشفّرة بـ argon2id، وتُسجَّل كل جلسة (الجهاز، المكان، الطريقة) |
| Google | الدخول بحساب Gmail **مرتبط مسبقاً** بالمستخدم في جدول `user_identities`. حساب Google غير مرتبط لا يدخل ولا يُنشئ حساباً تلقائياً |
| الربط | يربط المستخدم حسابه من «حسابي»، أو يربطه مدير النظام. حساب Gmail واحد لمستخدم واحد فقط (مختبَر T31) |
| الإيقاف | المستخدم الموقوف لا يدخل بأي طريقة. مدير النظام لا يستطيع إيقاف نفسه |

### سلسلة التبعية (من يعتمد لمن)

```
الإدارة المالية (هدى)
├── المشتريات (رفيق)
├── محاسب فرع الرياض (سارة)
├── مدير النظام (ناصر)
└── مدير المشروع (فيصل)
    └── المهندس (عمر)
        └── المراقب (خالد)
            └── الفني (راجيش)
```

تتبع الاعتمادات هذه السلسلة: المراقب يرى فريقه فقط، المهندس ومدير المشروع يريان مشروعهما، المحاسب يرى فرعه، والمشتريات والمالية ترى الشركة كلها. فواتير فرع جدة لا تظهر لفريق الرياض.

## 7. إدارة الحسابات وكلمات المرور (الإصدار 0.4)

**القاعدة: الشركة تتحكم في الحسابات وكلمات المرور.**

| الحالة | كيف تحدث | ماذا يحدث |
|---|---|---|
| إنشاء حساب | مدير النظام يضيف المستخدم: الدور، الفرع، المشروع، المسؤول المباشر | تُولَّد كلمة مرور مؤقتة يسلّمها المدير بنفسه |
| طلب حساب | الموظف يرسل طلباً من شاشة الدخول | يصل لمدير النظام؛ يعتمده بتحديد الدور والفرع والمشروع والمسؤول، أو يرفضه |
| أول دخول | بالكلمة المؤقتة | شاشة إلزامية لاختيار كلمة جديدة: 8 أحرف، حروف وأرقام، مختلفة عن الحالية |
| تغيير لاحق | من «حسابي ← الأمان» | يتطلب كلمة المرور الحالية |
| نسيان كلمة المرور | «نسيت كلمة المرور؟» في شاشة الدخول | طلب يصل للمدير، والرد واحد سواء وُجد الحساب أم لا (لا يكشف وجود الحسابات) |
| 5 محاولات فاشلة | تلقائي | الحساب يُقفل ويُبلَّغ المدير؛ لا يُفك إلا بإعادة التعيين |
| إعادة التعيين | المدير من صفحة المستخدم | كلمة مؤقتة جديدة، فك القفل، تغيير إلزامي عند الدخول |
| إيقاف | المدير | لا دخول بأي طريقة؛ لا يستطيع المدير إيقاف نفسه |
