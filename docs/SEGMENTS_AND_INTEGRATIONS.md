# الفئات والتكاملات — SEGMENTS_AND_INTEGRATIONS

**الإصدار:** 0.5 · 8 نوفمبر 2026

يخدم سمارت كاش ثلاث فئات بمنتج واحد. كل فئة **مساحة عمل** مستقلة ببياناتها، والانتقال بينها من شاشة الدخول. الفكرة: نبدأ ببساطة دفتر «أعطيت / أخذت» للفرد، ثم نضيف الطبقات كلما كبرت المنشأة، دون تغيير طريقة الاستخدام الأساسية.

---

## 1. لماذا ثلاث فئات؟

| | أفراد | مؤسسة صغيرة | شركة كبرى |
|---|---|---|---|
| **من؟** | موظف، صاحب عائلة، سائق، عامل يتعامل بالسلف | ورشة، محل، مقاول صغير: مالك + 2–20 موظفاً | 100–5,000 موظف، فروع ومشاريع ومناطق |
| **المشكلة** | ينسى من أخذ ومن أعطى، ولا يعرف أين ذهب راتبه | المالك يعطي العمال نقداً ولا يعرف أين صُرف، والعملاء يتأخرون في السداد | العهد بالملايين، فواتير ورقية، اعتمادات بطيئة، وقيود يدوية في ERP |
| **القيمة الأولى** | دفتر أعطيت/أخذت + مصروفاتي + تذكير واتساب | عهد العمال + اعتماد بضغطة + ديون العملاء | سلسلة اعتماد + حافظات + مطابقة ثلاثية + ERP |
| **من يعتمد؟** | لا أحد | المالك (خطوة واحدة) | 2 إلى 6 خطوات حسب المبلغ |
| **الأدوار** | حساب شخصي | مالك، موظف | 8 أدوار |
| **البيانات التجريبية** | أحمد الزهراني: 4 أشخاص، 41 مصروفاً، 3 عهد شخصية | مؤسسة الفهد للصيانة: مالك + 4 فنيين، 5 عملاء وموردين | 1,500 موظف، 6 فروع، 22 مشروعاً |
| **التكاملات** | روابط واتساب | روابط واتساب + واتساب للأعمال + برامج محاسبة المنشآت | كل ما سبق + SAP/Oracle/Dynamics + API |

## 2. فئة الأفراد

مستوحاة مباشرة من دفتر الديون في Konnash، مع إضافة المصروف الشخصي والعهد الشخصية.

### 2.1 الشاشات
| التبويب | المحتوى |
|---|---|
| **الرئيسية** | مصروف هذا الشهر مقابل الميزانية، منحنى 30 يوماً، «ستحصل / ستدفع / أمانات لديك»، تنبيهات (تصنيف قرب الميزانية، من يجب التحصيل منه، عهدة قاربت النفاد) |
| **الدفتر** | أعطيت / أخذت لكل شخص، الرصيد الجاري، **رسالة واتساب جاهزة بالرصيد**، كشف Excel |
| **المصروف** | الشهر الحالي والسابق، أشرطة التصنيفات مقابل الميزانية، القائمة مجمعة باليوم |
| **العُهد** | عهد **مستلمة** (مال أعطاك إياه أحد لتصرف عنه، مثل عهدة العمل) وعهد **مسلّمة** (أعطيت السائق أو العائلة مبلغاً). لكل عهدة: المتبقي، الصرف، تعزيز، تسوية، **كشف عبر واتساب** |

### 2.2 القواعد
- 10 تصنيفات شخصية: بقالة وطعام، وقود، فواتير وخدمات، مواصلات، صحة، تعليم، تسوق، عائلة، إيجار، أخرى.
- ميزانية شهرية لكل تصنيف؛ تنبيه عند 80% وعند التجاوز.
- صرف العهدة لا يتجاوز المتبقي (مختبَر T44)، والتسوية تسجّل إرجاع المتبقي.
- مصروف عهدة العمل **لا يُحسب** في مصروفك الشخصي، لأنه مال غيرك.

## 3. فئة المؤسسات الصغيرة

| الدور | يفعل |
|---|---|
| **المالك** | يصرف العهد ويعززها، يعتمد الفواتير بضغطة، يوقّع الحافظة (توقيع واحد يكفي)، يدير دفتر العملاء والموردين، يدير التكاملات والمستخدمين |
| **الموظف** | نفس تجربة الفني في الشركات: يصوّر الفاتورة، تدخل حافظته، يتابع حالتها، يصحح ما أُعيد |

**الشاشة الرئيسية للمالك:** صافي المركز (لك − عليك) · ما لدى الموظفين من عهد · صندوق الاعتماد · الأكثر مديونية مع زر واتساب مباشر لكل عميل · عهد الموظفين بأشرطة المتبقي.

**مسار الاعتماد:** خطوة واحدة («اعتماد المالك») بغض النظر عن المبلغ. التطبيق يحسب المسار حسب الفئة تلقائياً.

## 5. واتساب

### 5.1 مستويان

| | روابط واتساب (wa.me) | واتساب للأعمال (Cloud API) |
|---|---|---|
| **لمن** | كل الفئات | المؤسسات والشركات |
| **كيف** | يفتح واتساب في جوال المستخدم والرسالة جاهزة، وهو يضغط إرسال | يرسل النظام تلقائياً من رقم الشركة |
| **التكلفة** | مجاني | رسوم Meta لكل محادثة |
| **الموافقة** | لا شيء | تسجيل رقم في Meta Business، وقوالب رسائل تعتمدها Meta، وموافقة المستلم (opt-in) |
| **في النموذج** | **حقيقي**: الأزرار تفتح واتساب فعلاً | محاكاة: صندوق «المُرسل» يُظهر ما كان سيُرسل |

### 5.2 الرسائل الجاهزة (بلغة المستخدم)
| الرسالة | متى |
|---|---|
| «رصيدك لدينا X ر.س» | تذكير عميل مدين |
| «لك علينا X ر.س» | إشعار مورد دائن |
| «حسابك مسدَّد» | بعد التسوية |
| كشف العهدة المستلمة | للجهة التي أعطتك العهدة: المبلغ، المصروف، المتبقي، عدد البنود |
| كشف العهدة المسلّمة | للشخص الذي أعطيته: ما سُجّل من صرفه والمتبقي معه |

### 5.3 تنبيهات واتساب للأعمال (قابلة للتشغيل والإيقاف)
رفض فاتورة · إعادتها للتصحيح · وصول طلب لمعتمِد · اعتماد نهائي · صرف عهدة · تعزيز عهدة · اعتماد حافظة.

**لا تُرسل كلمات المرور عبر واتساب.** كلمة المرور المؤقتة يسلّمها مدير النظام بنفسه.

## 6. أنظمة ERP والمحاسبة

### 6.1 الأنظمة المدعومة
| النظام | الفئة | طريقة الربط في الإنتاج | الملف في النموذج |
|---|---|---|---|
| SAP S/4HANA | شركات | OData · Journal Entry API | XLSX |
| Oracle Fusion / NetSuite | شركات | REST · FBDI | CSV |
| Microsoft Dynamics 365 | شركات | Business Central API | XLSX |
| Odoo | مؤسسات | JSON-RPC · account.move | CSV |
| Zoho Books | مؤسسات | REST · journals | CSV |
| QuickBooks Online | مؤسسات | REST · JournalEntry | CSV |
| قيود Qoyod | مؤسسات (سعودي) | REST · قيود يومية | XLSX |
| دفترة Daftra | مؤسسات | REST · journals | XLSX |

### 6.2 ماذا يُرسل؟
لكل **حافظة معتمدة**، قيد يومية واحد:

| الحساب | مدين | دائن |
|---|---|---|
| مصروف كل تصنيف (5101 وقود، 5102 صيانة…) | صافي قبل الضريبة | |
| 1410 ضريبة المدخلات 15% | الضريبة | |
| 1130 عهدة الموظف CU-xxxxxx | | الإجمالي |

- المرتجعات (CN-) تُخصم قبل القيد.
- مركز التكلفة = المشروع + الفرع.
- **ربط الحسابات** قابل للتعديل: كل تصنيف إلى رقم حساب في دليل حسابات الشركة (3–10 أرقام، مختبَر T41).

### 6.3 القفل بعد الإرسال
بعد الإرسال الناجح تُقفل الحافظة: لا مرتجعات ولا تعديلات (مختبَر T42–T43). أي تصحيح لاحق يتم في ERP نفسه. هذا ما تفعله أنظمة الإنفاق الحديثة بعد التصدير المحاسبي.

### 6.4 الواجهة البرمجية والإشعارات الآلية (للشركات)
- `GET /v1/invoices?status=approved` · `POST /v1/invoices` · `POST /v1/approvals/{id}/decide` · `GET /v1/folders/{no}/journal` · `POST /v1/advances` · `GET /v1/ledger/contacts/{id}/statement`
- Webhooks: `invoice.submitted`, `invoice.approved`, `invoice.rejected`, `folder.closed`, `folder.approved`, `advance.issued`, `journal.exported`

## 7. ما استفدناه من SiFi

SiFi منصة سعودية لإدارة الإنفاق مرخّصة من البنك المركزي. أخذنا منها ما يناسب منتجاً لا يُصدر بطاقات:

| ميزة في SiFi | في سمارت كاش | الحالة |
|---|---|---|
| اعتماد جماعي (Bulk approve) | تحديد عدة طلبات واعتمادها مرة واحدة | ✅ 0.4 |
| التعليق على الطلبات مع إشعار الأطراف | تعليقات على الفاتورة وطلب الشراء، يُبلَّغ كل من له علاقة | ✅ 0.4 |
| تعديل المرفوض وإعادة إرساله | تصحيح وإعادة إرسال، أو التعديل قبل أول قرار | ✅ 0.4 |
| إضافة الرقم الضريبي ورقم الفاتورة والتاريخ | مع قراءة QR الضريبي تلقائياً | ✅ 0.3 |
| ميزانيات الفرق مع تنبيه قرب الحد | ميزانية المشروع (فواتير + أوامر شراء) وميزانيات الأفراد | ✅ 0.4–0.5 |
| قفل السجلات بعد التصدير المحاسبي | قفل الحافظة بعد إرسال القيود | ✅ 0.4 |
| ربط دليل الحسابات وتصدير القيود | ربط الحسابات + 8 أنظمة | ✅ 0.5 |
| تنبيهات SMS وبريد | تنبيهات واتساب للأعمال (أكثر استخداماً في المملكة) | ✅ 0.5 |
| تسجيل الأجهزة، والدخول الموحد (SSO) | سجل الجلسات والأجهزة؛ SSO مخطط للشركات | جزئي |
| بطاقات الشركة والتحويلات البنكية | **خارج النطاق**: تتطلب ترخيص البنك المركزي | — |

## 8. ما لم يُحلَّل

**الرابط المشارك من فيسبوك (Reel):** فيسبوك يمنع القراءة الآلية لصفحاته، فلم أتمكن من مشاهدته. إذا أرسلت لقطات شاشة منه أو وصفاً لما يعرضه، أضيف تحليله هنا وأطبق ما يناسب منه.

## 9. ما يُحاكى في النموذج وما سيكون حقيقياً

| | في النموذج | في التطبيق |
|---|---|---|
| روابط واتساب | **حقيقية** | نفسها |
| واتساب للأعمال | محاكاة بصندوق صادر | WhatsApp Cloud API بقوالب معتمدة |
| ملفات القيود CSV/XLSX | **حقيقية** | نفسها + إرسال آلي |
| الإرسال إلى ERP | محاكاة: يقفل الحافظة ويسجّل مرجعاً | استدعاء API الفعلي، مع إعادة المحاولة وسجل أخطاء |
| أسرار الربط | لا تُخزن | في خزنة أسرار (`secret_ref` فقط في القاعدة) |
